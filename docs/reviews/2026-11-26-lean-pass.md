# Lean pass review (2026-11-26)

Scope: find dead code and slow spots, simplify where safe, keep every feature.
Branch `review/lean-pass`, not merged. Railway deploys `main`, and no feature
was removed without the owner's say-so.

## Result in one line

The app is already lean. Little is dead, the heavy client libraries already
load lazily, and the real size is in a few large files. I removed what was
provably dead and listed the rest as decisions for the owner.

## What I checked

- **Dead code.** A script compared every `lib/` export against every use in `lib/`, `app/`, `components/`, `scripts/` and `test/`. Only 4 exports were used nowhere, not even inside their own file.
- **Dependencies.** Every runtime dependency is imported. The few that never appear in source (`tailwindcss`, `postcss`, `autoprefixer`, `typescript`, `eslint-config-next`, `react-dom`) are used by build config or the framework.
- **Client weight.** Total static JS is about 2.3 MB. The largest chunk (about 1 MB, three.js) loads only on `/mind` through `next/dynamic`. Leaflet loads only on `/map`. PostHog is imported dynamically. Nothing to gain here.
- **Database.** 27 indexes already cover the hot lookups (`pages`, `entry_entities`, `chat_memories`, `ocr_flags`, `api_usage`), and search uses FTS5.
- **Background work.** The maintenance sweep is throttled internally and runs every 5 minutes. Page loads also call it, but it exits early when not due.

## Changed on the branch

- Removed `MAP_UNLOCK_TTL_MS` (`lib/mapPin.ts`) and `entityWikiAutoEnabled` (`lib/entityWiki.ts`). Neither was used anywhere.
- Kept `consentSecretValid` (`lib/mcpOauth.ts`). It is unused, but `CLAUDE.md` names it as the OAuth consent gate, and `matchConsentSecret` does the real work. Remove it only together with those doc lines.
- Left `startBackgroundMaintenanceScheduler` alone. It is called from `instrumentation.ts`, which my scan did not cover.

Checks: `tsc` clean, lint 0 errors (2 existing warnings in `app/notebooks/page.tsx`), 827 tests pass, build passes.

## Where simplification would pay off (not done: risky unattended)

Large files with mixed jobs: `app/memory/page.tsx` (1,912 lines), `lib/claude.ts` (2,028), `lib/notes.ts` (1,646), `lib/dropbox.ts` (1,485), `lib/mcp.ts` (1,172). Splitting them would make them easier to navigate but would not make the app faster. Each split touches code guarded by "do not regress" rules, so it should be done one file at a time with the owner awake.

## Second pass: runtime efficiency (three read-only reviews, findings checked by hand)

Applied on the branch (tests 828 pass, build and lint clean):

- **SQLite settings** (`lib/db.ts`): `synchronous=NORMAL`, memory temp store, 64 MB page cache, 256 MB memory-mapped reads. With WAL an app crash loses nothing; only a power cut can drop the last commit, and the weekly backup covers that.
- **Semantic search** (`lib/chatTools.ts`): the scan of up to 2000 pages no longer loads every page's text (about 4 MB per `search_diary` call); text is read only for the returned hits. Same results.
- **/mind map** (`lib/mind.ts`): reads the 200-character preview in SQL instead of whole page texts.
- **Life wiki** (`lib/entityWiki.ts`): failed attempts now count against the pass limit and two failures in a row end the pass. Before, an API outage meant one Claude call for every stale entity, every 5 minutes. Test: `test/entityWikiOutage.test.ts`.
- **/notebooks**: the 4-second refresh no longer restarts itself on every result (also clears one lint warning). Proofreading card pictures load lazily.

Not done, in order of value (each needs care or your say-so):

1. **Backup** (`lib/backup.ts`): `cp`/`tar` run synchronously (the server stalls for the length of the copy), and the archive is held in memory about 5 times over. Switch to async `tar` and drop copies early; keep the encrypted round-trip check and the `decrypt-backup.mjs` format.
2. **Dropbox export**: each notebook sync renders the whole vault and re-uploads unchanged notes. Remember a hash per uploaded file and skip identical ones; read the diary data once per export.
3. **/graph**: the page waits on Dropbox downloads when its cache is cold and rebuilds the graph twice if that fails. Build the graph once and load vault notes after.
4. **Full-text index deletes** scan the whole table (a 300-page import costs a few seconds of blocked server). Needs an index rebuild migration.
5. **Embedding retries**: a page the embedding service keeps rejecting is retried every 5 minutes forever. Record failures and back off.
6. **OCR prompt caching**: put the handwriting examples before the PDF and cache them. Could change transcription slightly, so test on real pages first.
7. **/memory** fires about 12 requests at load from one 1,900-line component; **/notebooks** list reads every page's text just to count pages.

Left alone on purpose: one-file-at-a-time splits of the large files, and anything touching auth, PIN gates, exclusion lists, tombstones or the export invariants.
