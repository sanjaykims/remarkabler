# Lean pass review (2026-11-26)

Scope: find dead code and slow spots, simplify where safe, keep every feature.
Branch `review/lean-pass`, not merged. Railway deploys `main`, and no feature
was removed without the owner's say-so.

## Result in one line

The app is already lean. Little is dead, the heavy client libraries already
load lazily, and the real size is in a few large files. I removed what was
provably dead and listed the rest as decisions for the owner.

## What I checked

- **Dead code.** A script compared every `lib/` export against every use in `lib/`, `app/`, `components/`, `scripts/` and `test/`. Only 4 exports were used nowhere, not even inside their own file.
- **Dependencies.** Every runtime dependency is imported. The few that never appear in source (`tailwindcss`, `postcss`, `autoprefixer`, `typescript`, `eslint-config-next`, `react-dom`) are used by build config or the framework.
- **Client weight.** Total static JS is about 2.3 MB. The largest chunk (about 1 MB, three.js) loads only on `/mind` through `next/dynamic`. Leaflet loads only on `/map`. PostHog is imported dynamically. Nothing to gain here.
- **Database.** 27 indexes already cover the hot lookups (`pages`, `entry_entities`, `chat_memories`, `ocr_flags`, `api_usage`), and search uses FTS5.
- **Background work.** The maintenance sweep is throttled internally and runs every 5 minutes. Page loads also call it, but it exits early when not due.

## Changed on the branch

- Removed `MAP_UNLOCK_TTL_MS` (`lib/mapPin.ts`) and `entityWikiAutoEnabled` (`lib/entityWiki.ts`). Neither was used anywhere.
- Kept `consentSecretValid` (`lib/mcpOauth.ts`). It is unused, but `CLAUDE.md` names it as the OAuth consent gate, and `matchConsentSecret` does the real work. Remove it only together with those doc lines.
- Left `startBackgroundMaintenanceScheduler` alone. It is called from `instrumentation.ts`, which my scan did not cover.

Checks: `tsc` clean, lint 0 errors (2 existing warnings in `app/notebooks/page.tsx`), 827 tests pass, build passes.

## Not changed (needs the owner's decision)

These are real features. I could not tell from the code whether they are used, so none was touched.

| Candidate | Why it might go | Cost of keeping |
|---|---|---|
| `/map` + OwnTracks + location tools | Needs the phone app and a PIN; only matters if used | about 1,000 lines, Leaflet chunk (lazy) |
| `/mind` 3D embedding map | Heaviest client chunk (about 1 MB, lazy) | no cost unless opened |
| GitHub "discipline" sync | Separate source | one sync job |
| Librarian tools (`MCP_ALLOW_WIKI_LINKING`) and auto-tag | Off by default; need an external agent | about 1,500 lines |
| `export/book` editor pass | Occasional Opus call | one route |

Check usage first: the `mcp_audit` table shows which MCP tools get called, and
`/usage` shows which Claude calls cost money.

## Where simplification would pay off (not done: risky unattended)

Large files with mixed jobs: `app/memory/page.tsx` (1,912 lines), `lib/claude.ts` (2,028), `lib/notes.ts` (1,646), `lib/dropbox.ts` (1,485), `lib/mcp.ts` (1,172). Splitting them would make them easier to navigate but would not make the app faster. Each split touches code guarded by "do not regress" rules, so it should be done one file at a time with the owner awake.
