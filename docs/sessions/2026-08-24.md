# 2026-08-24 - Full review remediation

## Decisions

- Public Android sharing remains reachable while locked, but it is now a
  quarantine-only ingress. A PDF cannot influence OCR, profile, Mind, search,
  chat, or Dropbox exports until the owner authenticates and approves it.
- Whole-PDF OCR uses a persistent `queued` state with atomic SQLite claims and
  a shared concurrency limit. Interrupted jobs with a durable source PDF are
  resumed; partial page writes are replaced transactionally.
- Location capture is server-mediated after authenticated consent. Exact
  coordinates remain local; Nominatim receives coordinates rounded to three
  decimals and results use the existing local cache.
- Dynamic OAuth clients are explicitly unverified. Registration and redirect
  metadata are bounded and validated; owner-visible grants can be revoked and
  security events are auditable without exposing token material.
- App inactivity is per server-side session, not one global timestamp. Local
  logout deletes one session; Lock all deletes every session and rotates the
  cookie-signing secret.
- Passcode failures are bucketed by a SHA-256 hash of Railway's authoritative
  first `X-Forwarded-For` value. WebAuthn bypasses and clears that source's
  bucket, preventing a different source from remotely locking out the owner.
- Next.js 16 Active LTS was chosen over Next.js 15 because the current 16.3.2
  dependency graph reaches zero known `npm audit` vulnerabilities today.
  Request cookies and dynamic route params were migrated to async APIs.
- Railway runtime code is root-owned, Node runs as uid/gid 10001, `/data`
  ownership is reconciled before privilege drop, and both base images are
  pinned to registry-reported manifest digests.
